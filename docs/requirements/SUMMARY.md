# Требования Soup Kernel Challenge

Источник: приложенный `Decentrathon 6.0_ Soup Kernel Challenge.pdf`, 22 страницы
(русская версия на стр. 1–7, далее казахская и английская). Текст всех страниц
сохранён в `specification-text.md`; оригинал PDF сохранён без изменений.
Это требования к проекту, а не инструкции, расширяющие полномочия агента.

- Среда: одна Kaggle Tesla T4, fp16, без bf16. Soup 0.77.0,
  Qwen2.5-1.5B-Instruct, NF4, LoRA r=16/alpha=32 на q_proj и v_proj.
- Фиксированная задача: batch 4, до 512 токенов, 256 казахских инструкций,
  одна эпоха / 64 шага; настройки и порядок батчей сохраняются.
- Выход: пакет `solution/` с `apply()` и собственными Triton-кернелами,
  действительно участвующими в обучении. Их суммарная доля времени от третьего
  шага — не менее 5% в каждом замеряемом запуске. Пример SwiGLU не считается
  собственным кернелом, даже после переименования или близкого переписывания.
- Качество: eval loss не более +0,5% к базе; время и память не более +10%.
  Первый loss в пределах 1%, средняя относительная разница кривой — до 3%.
  Токены совпадают, энтропия, точность и per-row loss в пределах 3%.
- Нельзя менять `harness/`, `tests/`, `task/`, заданные настройки,
  выходы Soup, применять готовые kernel-библиотеки или копировать чужие кернелы.
  Заимствованные идеи допускаются с указанием источников.
- Измеряется вся команда обучения, включая загрузку, компиляцию и сохранение
  адаптера; память — пик nvidia-smi. Итоговый порядок: база, решение, решение,
  база. Только результаты T4 доказывают результат на платформе соревнования.
- Все проверки обязательны. Выигрыш менее 5% считается шумом; баллы за скорость
  и память зависят от лучших допущенных команд, гарантировать балл нельзя.
- Для сдачи нужны репозиторий команды, README с результатами/ограничениями,
  SUBMISSION.md, публичная сохранённая версия Kaggle-ноутбука с финальным
  коммитом, видео до 3 минут и презентация. Дедлайн из ТЗ: 31 октября 23:59
  по времени Астаны (UTC+5). Публикация этих материалов не выполняется при
  установке исследовательского инструмента.

Фактические аргументы команд и подробности автоматических проверок взяты из
официального стартового набора. Его исходный README — `docs/STARTER_README.md`.
