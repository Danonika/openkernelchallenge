# Soup research additions — first pass, 2026-10-30

**Precision correction from focused pass:** Accelerate 1.14.0 wraps the model's autocast forward with recursive `convert_outputs_to_fp32`. Thus baseline logits consumed by TRL and rewind are expected to be FP32 values upcast from the fp16 head. Soup's optional chunked helper computes metrics internally in head dtype; that helper is a protocol reference, not the exact baseline numeric oracle. The SOUP-NEW-002 head-dtype statement below describes that helper and must not be applied to baseline trainer-visible logits. Verify the actual prepared-model boundary on T4. See the companion dataflow plan.

## Findings to act on
1. Prioritize the output-head pipeline as **one semantic unit: CE + entropy + accuracy + rewind**, not CE alone. TRL entropy covers all attention-masked tokens, including prompt and final positions; accuracy/CE use shifted assistant labels. Soup v0.77.0 already exposes a logits-free metrics/rewind contract.
2. Nanochat does **not** implement chunked CE in the inspected revision: its GPT forward contains a TODO. Its useful transferable idea is narrow AdamW update fusion with changing scalar values supplied at runtime; its Muon/architecture/FP8 improvements are not legal Soup changes.
3. Public same-challenge designs now exist, but the two inspected result tables have placeholders/TBD. They supply hypotheses, **not verified Kaggle speedups**.
4. This pass wrote no kernel implementation, imported no prohibited library, installed nothing, ran no benchmark, and made no remote edits.

## Existing IDs worth promoting instead of duplicating
- **liger_castaware_norm**, **vllm_vector_norm**, **xformers_rms_cachepolicy**, **sglang_norm_boundary**: own Qwen2 RMSNorm / add+RMSNorm forward and backward, preserving fp32 residual and reference casts. P0/P1.
- **trt_qknorm_rope_fusion**, **attn-sgl-rounding-fusion**: only transfer RoPE layout/rounding ideas; do **not** add QK normalization absent from Qwen2. P2.
- **L6-16**, **inductor_b2b_fusion**: potential rank-16 LoRA fusion; preserve separate q/v dropout draws and gradients. P2.
- **L4-RIGHTNOW-AI-AUTOKERNEL-02**, **L4-APACHE-TVM-03**: budget tuning by complete-run gain, including cold compilation. P0 methodology.
- **L1-CUTLASS-01**, **L1-TRITON-03**, **gemm-01**, **gemm-03**, **attn-fa-paged-copy-overlap**: do not directly transfer Hopper TMA/WGMMA or Ampere cp.async machinery to T4.

## Validation gates
Rules R require own useful solution-defined Triton kernels >=5% of training time (steps 3+, lowest run); no artificial busy work. Starter SwiGLU and Inductor kernels do not count. First loss within 1%, mean loss within 3%, held-out loss <=0.5% worse; entropy/accuracy/rewind losses within 3%; exact structural/token/row invariants. Time and memory <=10% worse; all 79 regression tests; only Kaggle T4 counts.

First run a targeted fp16 oracle for logits rounding, gradient scaling/overflow, ignored labels, all-ignored rows, ties in argmax, prompt-only/final-token entropy, ragged batches and dropout RNG. Then full unchanged harness with cold caches and saved plain-PEFT adapter evaluation. Do not use an algebraic equality argument as evidence of floating-point equivalence.
