## Precise hypothesis and change from failed trial009

The original materialized loss computes centered vocabulary log probabilities with tiled Triton reductions instead of native CE's full-vocabulary FP32 cast/log-softmax state. The model's existing FP16 head logits, returned FP32 logits, trainer, entropy/accuracy, rewind outputs and saved adapter remain untouched. This may reduce CE transient memory and work; **the whole-task effect is unmeasured** and competing full-logit metrics still exist.

V3 is not an unchanged trial009 rerun:

1. **One denominator host read.** Trial009 called `.item()` on the supplied CUDA denominator both in the adapter and again in the core. V3 validates it once in the core and records metadata there. It still divides the native FP32 summed loss by the **original supplied object**, preserving its autograd version behavior and native external normalization/scaling order. No recounting supervision, replacing the denominator, late-half gradient scaling or gradient unscaling.
2. **Captured-native fallback.** Internal backend/denominator/numerical-guard fallbacks now call the captured native `ForCausalLMLoss` with the original arguments and keyword objects. Unknown keys, alternate labels/ignore indices and unsupported bool/control types remain native. Only exact `bool`/`None` forms of the two pinned loss-ignored output-control keywords are permitted on the optimized route.
3. **Timeout-visible integration evidence.** A compact flushed JSON record is emitted on each loss boundary, selected native/own forward route and backward enqueue; one additional start marker precedes the first JIT. This does not wait for `atexit`. Metadata contains only shapes/types/allowed controls/counters, never labels, activations or gradients. Counters are bounded to 129 keys each. Normal optimized training uses about three event records per loss call, plus fixed installation/first-prepass/final records. I/O and remaining guard synchronization costs count in measured wall time; their overhead is **not yet measured**.

All five Triton kernel ASTs, native standalone loss expression and numerical-gate bytes are unchanged from trial009. Native SUM reduction, supplied-denominator division, FP32 normalized upstream and final FP16 gradient narrowing retain their order; FP fusion remains disabled. The strict near-certain/nonfinite/invalid-target whole-call fallback is preserved outside `no_grad`. This is numerical-contract preservation by source inspection, **not** proof of CUDA numerical equality.
