# Duo — Soup Kernel Challenge

Автоматический исследовательский цикл для поиска оптимизаций Soup на Kaggle T4,
адаптированный из [Auto-research-agent](https://github.com/rohanarun/Auto-research-agent).
В репозиторий включены официальный стартовый набор Soup, техническое задание и
локальный плагин Codex **Soup Auto Research**.

**Текущее состояние:** готова инфраструктура поиска. `solution/` содержит только
официальный пример SwiGLU; собственные оптимизации ещё не разработаны, результатов
команды на GPU пока нет. Пример не выполняет требование о собственных кернелах.

## Исследование в Codex

Откройте этот репозиторий как проект Codex. Установленный плагин предоставляет
навык `$soup-research`. Пример запроса:

> Используй $soup-research. Прочитай ТЗ и предложи одну проверяемую гипотезу
> оптимизации. Пока без GPU-запусков; сохрани результаты в RESEARCH_HANDOFF.md.

Для установки из локальной копии (Codex CLI с командами `plugin`):

```sh
codex plugin marketplace add .
codex plugin add soup-auto-research@duo-soup-local
codex plugin list --marketplace duo-soup-local --json
```

После установки начните новый чат в проекте, чтобы загрузился навык. Для самой
установки не нужны API-ключи, GPU или macOS. Исходное macOS-приложение не требуется.

## Отдельный автоматический запуск

Требуются Python 3.10+ и установленный Codex CLI с выполненным `codex login`.
Координатор использует только стандартную библиотеку Python. Предпросмотр не
запускает модель, GPU и не создаёт файлы:

```sh
python scripts/auto_research.py --dry-run
```

Один исследовательский раунд без GPU (расходует лимит Codex):

```sh
python scripts/auto_research.py --execute --max-rounds 1 --gpu-runs 0
```

До трёх раундов с автоматическим продолжением и лимитом 15 минут на каждый:

```sh
python scripts/auto_research.py --execute --keep-researching --max-rounds 3 --timeout-seconds 900 --gpu-runs 0
```

Своя цель передаётся через `--prompt`, модель — необязательным `--model`.
Без `--model` используется стандартная модель CLI. Отдельный процесс запускается
с `--ignore-user-config`, отключёнными плагинами/apps/multi_agent и sandbox
`workspace-write`: глобальные интеграции и настройки модели не наследуются.
Проектные ограничения и ограничения среды по-прежнему действуют. Учётные данные
CLI используются штатно; координатор их не копирует. Это обычный запуск CLI,
а не отдельный аппаратный контейнер безопасности.

Продолжение происходит только после `RESEARCH_STATUS: continue`, при включённом
`--keep-researching` и наличии handoff. `needs_input`, `finished`, отсутствие
статуса, ошибка, таймаут или лимит раундов останавливают цикл. Перед/после раунда
проверяются хеши замороженных входов. `Ctrl+C` останавливает принадлежащее запуску
дерево процессов и сохраняет состояние. После аварии ОС может остаться
`.research/active.lock`: прежде чем удалить его, проверьте записанный в нём PID.

Запросы, события, ответы и `state.json` лежат в `.research/runs/` (не в Git).
Выводы и оставшиеся проверки — в [RESEARCH_HANDOFF.md](RESEARCH_HANDOFF.md).
Сохраняйте сырые измерения до следующего запуска официального harness: он может
перезаписать прежние результаты в выбранной папке.

`--gpu-runs` — общий бюджет вызовов GPU-harness, переданный агенту как инструкция;
это не аппаратный счётчик и не ограничение расходов провайдера. По умолчанию он
равен нулю. Лимиты раундов и времени координатор применяет программно. Он не
подключается к Kaggle автоматически: для реальных экспериментов нужен доступный
T4 и заранее установленная среда. Платные ресурсы и сдача на конкурс не запускаются.

## Проверка на Kaggle T4

Импортируйте [ноутбук](templates/kaggle_notebook.ipynb) в свой Kaggle, включите
GPU T4 x2 и Internet. URL репозитория уже заполнен. Для приватного репозитория
нужен Kaggle secret `GITHUB_TOKEN` с правом чтения. Код harness использует одну
карту. Выполните Run All. Перед финальной сдачей укажите точный COMMIT и сохраните
публичную версию ноутбука с выводами.

Полные команды установки зависимостей — в исходном README и ноутбуке. В готовой
Linux/CUDA-среде:

```sh
python task/prepare_data.py
python -m pytest solution -q
python harness/run_task.py --repeats 2
python harness/check_rules.py
```

`harness/`, `tests/`, `task/` сохранены без изменений. Исследовательские тесты
отделены от проверок организаторов. Только `solution/` переносится жюри в чистый
стартовый набор, поэтому исследовательский инструмент не участвует в замере.

| Метрика команды | База | Решение |
|---|---|---|
| Полное время обучения | Не измерено | Не измерено |
| Пик памяти T4 | Не измерено | Не измерено |
| Eval loss | Не измерено | Не измерено |
| Собственные кернелы и все 10 проверок | — | Ещё не выполнено |

Публичный Kaggle-ноутбук команды: **ещё не создан**. Остальные материалы и ссылки
для сдачи отмечены в [SUBMISSION.md](SUBMISSION.md). Значения из примеров ТЗ или
README организаторов не являются результатами команды.

## Проверка инфраструктуры без GPU

```sh
python -m unittest discover -s research_tests -v
python scripts/auto_research.py --dry-run
```

Тесты проверяют поведение продолжения, ошибки, лимиты, handoff, целостность входов
и работу процессов. Они не запускают модель и не подтверждают корректность
Triton-кернелов или ускорение обучения.
