# Soup Kernel Challenge

[English version](README.md)

Оптимизация обучения LoRA на одной NVIDIA Tesla T4. В репозитории собраны итоговое решение, парный замер, исследовательские эксперименты и инструменты для их запуска и проверки.

## Итоговый замер

Сохранённая сессия Kaggle v1: **база → решение → решение → база** на одной T4. В этой сессии прошли **10 из 10 автоматических проверок** и **79 из 79 регрессионных тестов**.

| Метрика | Базовый вариант | Решение |
|---|---:|---:|
| Полное время команды, медиана двух запусков | 86,39 с | **47,73 с (ускорение в 1,81 раза)** |
| Время цикла обучения, медиана двух запусков | 62,95 с | **33,63 с** |
| Пиковая память GPU, максимум двух запусков | 14 345 MiB | **2 263 MiB (на 84,2% меньше)** |
| Потери на отложенной выборке | 2,04966 | 2,04984 (+0,009%) |

[Исходные метрики](docs/evidence-final-v1/result.json) · [Автоматические проверки](docs/evidence-final-v1/checks.json) · [Правила замера](docs/CHALLENGE_CONTRACT.md)

Это исторические измерения, а не повторный запуск очищенной публичной копии. Автоматические проверки не подтверждают решение жюри или место в соревновании.

## Что сделано

- **Выходная проекция и функция потерь:** обработка всех 151 936 элементов словаря блоками без хранения полного тензора логитов.
- **MLP и память активаций:** пересчёт gate/up-проекций в обратном проходе и группировка операций на поддерживаемых путях.
- **NF4 и QKV:** общая деквантизация совместимых проекций и группировка QKV без изменения формата хранения весов.
- **RMSNorm, RoPE и padding:** меньше промежуточных буферов, приведений типов и лишней работы на строках заполнения.
- **Интеграция и проверка:** включение оптимизаций через `solution.apply()`, штатная нагрузка Soup, оценка потерь, контроль выходов и проверка активности оригинальных ядер. Формат сохранённого LoRA-адаптера не меняется.

Идеи и разбор исходников, задания очереди и измеренные прогоны учитывались отдельно. Строка каталога или подготовленный ноутбук не доказывают ускорение. Повторные попытки, отклонённые идеи, незавершённые прогоны и замеры с другой базой не складываются с итоговым бенчмарком.

В заметках по replay и выходной проекции сохранены и более узкие результаты:

- **Replay сохранённого состояния LoRA:** прошли 66 из 66 сравнений; расчёт на CPU дал **12 MiB на пару**. Последующие проверки прошли в 41 из 41 случая в интерпретаторе и в 9 из 9 случаев с CPU autograd. Это не подтверждает работу всей цепочки на GPU или экономию видеопамяти.
- **Резервный путь выходной проекции с точными шкалами:** **72,87 с / 5 363 MiB**, прошли 79 регрессионных тестов; парной базы для этого прогона нет.
- **NF4 с упаковкой в машинные слова:** вариант с регрессией отклонили. 79 пройденных тестов у других вариантов не подтверждают отклонённый.

В одном эксперименте очереди совместили упакованный replay для T448 и блок выходной проекции на 4 096 токенов при N = 1 024. Зафиксировано **38,12 с для команды обучения, 25,65 с внутри цикла, 94,09 с для всего задания и 2 261 MiB пиковой памяти**. Вариант обошёл **сохранённый оптимизированный контроль** за 38,49 с при 2 261 MiB по внутренним проверкам времени, потерь и памяти. Это не свежий парный замер и не замена итоговому парному результату 47,73 с.

Отдельная [проверка fast-v2](research/runs/20261031-allresearch-approved/) дала **62,71 с / 7 955 MiB** без свежей парной базы. Попытка с меньшим потреблением памяти остановилась на **46-м шаге из 64**, поэтому её пик нельзя считать результатом полного прогона.

## Как запустить

Откройте [ноутбук Kaggle](notebooks/Soup-Duo-Final-Submission-v1.ipynb) и выберите одну T4. Ноутбук проверяет контрольные суммы 38 встроенных файлов. Для загрузки пакетов, модели и датасета нужен интернет; токен GitHub и дополнительные ветки не нужны.

В подготовленной CUDA-среде из корня репозитория:

```bash
python -m pip install -r requirements.txt
python task/prepare_data.py
python harness/run_task.py --repeats 2 --timeout 900
python harness/check_rules.py
python harness/score.py runs/result.json
```

Нагрузка: Qwen2.5-1.5B-Instruct, Soup 0.77.0, NF4 с двойной квантизацией и вычислениями FP16, LoRA для `q_proj` и `v_proj` (`r=16`, `alpha=32`), 256 инструкций и 64 шага, batch 4, длина до 512 токенов. Полное время включает подготовку, компиляцию, обучение и сохранение адаптера.
